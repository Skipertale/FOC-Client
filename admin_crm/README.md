# FoC Admin CRM

Тёмно-фиолетовая CRM-панель для администрации Attorney Online / KFO.

## Что умеет

- читает серверные данные из `storage/db.sqlite3`
- строит вкладку **Игроки** как агрегированный реестр по **HDID**
- показывает последние OOC/IC-имена, персонажей, IP, дату первого и последнего входа, количество подключений и наличие банов
- даёт вкладку **Профили** для ручных админских карточек
- умеет искать по ключевым данным карточки: HDID, OOC, IC, персонаж, IP, названия профилей, Discord, теги, заметки
- позволяет привязывать **несколько HDID** к одному профилю
- один и тот же **HDID** автоматически удерживается только за одним профилем
- поддерживает дополнительные поля: `status`, `risk_level`, `tags`, `notes`
- показывает в карточке игрока серверные логи: последние сообщения и действия с фильтрами
- умеет пересобирать кэш и экспортировать список игроков в CSV
- автоматически показывает время в МСК
- синхронизирует кэш в фоне, без блокировки открытия страниц
- автоматически подтягивает новые входы и свежие area-события без ручной полной пересборки
- использует **аккаунты CRM** вместо общего пароля
- первый зарегистрированный пользователь автоматически становится **главным администратором**
- все последующие пользователи создаются как обычные и ждут, пока ГА выдаст им доступ к панели
- у ГА есть отдельная вкладка **Пользователи** для выдачи и отзыва доступа

## Архитектура

Поскольку в исходной базе нет готовой таблицы `players`, панель собирает сущность игрока сама:

- источник истины: `storage/db.sqlite3`
- внутренняя база CRM: `admin_crm/crm.sqlite3`
- кэш игроков строится по `connect_events`, `area_events`, `ipids`, `hdid_bans`, `ip_bans`
- после первого полного построения дальнейшие обновления идут инкрементально в фоне
- основная сущность — **HDID**
- админские профили хранятся отдельно и привязываются к одному или нескольким HDID
- аккаунты CRM и сессии тоже хранятся в `crm.sqlite3`

## Запуск

Из корня сервера `FoC`:

```bash
cd admin_crm
python app.py --host 127.0.0.1 --port 8080
```

Откроется сайт по адресу:

```text
http://127.0.0.1:8080
```

После первого запуска:

1. откройте `/register`
2. создайте первый аккаунт
3. этот аккаунт сразу станет **главным администратором**
4. все следующие аккаунты будут видеть экран ожидания, пока ГА не выдаст доступ во вкладке **Пользователи**

## Полезные параметры

```bash
python app.py --source-db ../storage/db.sqlite3 --crm-db ./crm.sqlite3 --host 0.0.0.0 --port 8080 --force-sync
```

## Переменные окружения

```bash
CRM_SECRET_KEY=your_random_secret
CRM_HOST=127.0.0.1
CRM_PORT=8080
```

`CRM_ADMIN_PASSWORD` больше не нужен: вход работает через собственные аккаунты CRM.

## Что лежит в CRM-базе

- `player_cache` — подготовленный реестр игроков по HDID
- `profiles` — ручные карточки админов
- `profile_hdids` — связи профилей и HDID
- `accounts` — аккаунты CRM
- `account_sessions` — активные сессии входа
- `meta` — служебная информация о синхронизации

## Рекомендация по продакшену

Лучше держать `storage/db.sqlite3` только источником чтения, а запись CRM-данных оставлять в `admin_crm/crm.sqlite3`.
